## 固定本地预览地址

用户痛点：本地预览地址老变，每次都要重新输入。

原因定位：
- `open-local-web.bat` 用的 `scripts/local-static-server.cjs` 本来就是固定 `127.0.0.1:4173`
- 但 vite dev / preview 端口没固定，默认 5173 / 4173，被占用时静默递增导致地址漂移

改动：`vite.config.ts`
- `server`: host `127.0.0.1` + port `5173` + `strictPort: true`（开发模式固定）
- `preview`: host `127.0.0.1` + port `4173` + `strictPort: true`（构建产物预览固定）
- 注意：不要动 `chunkSizeWarningLimit`（第一次编辑误删已恢复）

最终固定地址：
- 开发热更新（npm run dev）：`http://localhost:5173`
- 构建产物预览（build-and-open-local-web.bat / 手动启动 local-static-server）：`http://localhost:4173`

本次已启动 4173 静态服务器提供预览（后台 task 记录在会话内）。

## 8月26日-1：API 总开关

用户场景：测试导入数据时，后台主动消息 / 日程 / 家园等自动流程会反复调 LLM 浪费钱。要一个总开关。

实现：

1. **新文件 `utils/apiMasterSwitch.ts`**
   - 照搬 `utils/analytics.ts` 风格：localStorage key `os_api_master_enabled`，默认开启
   - 导出 `isApiMasterEnabled()` / `setApiMasterEnabled(bool)` / `onApiMasterChange(listener)`
   - 自定义 `ApiMasterDisabledError`（带 `code: API_MASTER_DISABLED_CODE`）便于上层 catch 区分
   - 跨标签页 storage 事件同步

2. **`utils/safeApi.ts` 拦截点**
   - 在 `safeFetchJson` 函数体最开头（retryableStatuses 之前）检查
   - 关闭时 throw `ApiMasterDisabledError`
   - **不写 devDebug 日志**——用户主动关的，不是 API 异常
   - 一个出口 = 一处拦截：LLM / TTS / 生图 / 识图 / 嵌入 / 联网代理全走 safeFetchJson

3. **`apps/Settings.tsx` UI**
   - 新增独立组件 `ApiMasterSwitchCard`（不用 SettingsSection，因为要默认展开、视觉强调）
   - 位置：第 2145 行滚动容器顶部、第一个 SettingsSection 之前
   - 视觉：状态色（绿/红）边框 + PlugsConnected 图标 + 状态 chip（运行中/已停用）
   - 大开关 + 拦截范围说明
   - 关→开 直接生效；开→关 走二次确认（避免误触导致角色停摆、主动消息断流）

版本号：`utils/buildInfo.ts` APP_VERSION 改为 `8月26日-1`，`public/version.json` 同步。

构建注意事项：
- WorkBuddy 的 `genie-safe-delete.cjs` 安全删除工具在 trash `dist/amsg-worker.bundle.js` 等文件时偶发 abort 失败
- 解决：构建前手动 `Remove-Item dist -Recurse -Force` 整目录删除，避开逐文件 trash

## 8月26日-3：AI 气泡尾巴 + 头像对齐修复

用户反馈 AI 侧单行气泡的尾巴位置错乱、且没和头像框顶部对齐。

### 根因（三个参照系混用）
1. **AI 侧 `renderBubbleTail` 直接返回 null**（`MessageItem.tsx:2012`）—— AI 不渲染 JSX SVG，完全靠 `apps/Chat.tsx:3193-3221` 复古微信分支下的伪元素 PNG
2. **PNG 文件不存在**（`dist/chat-themes/retro-wechat-tail-ai.png` 等），伪元素 `background: url(...)` 加载失败
3. **伪元素 `top: var(--sully-tail-top) = calc(avatar-size/2 - tail-h/2) = 6.5px` 是绝对像素**（`apps/Chat.tsx:3215-3221`），挂在 `.sully-bubble-layer::before` 上，**不跟随气泡的 `margin-top: 8px`**（`--sully-chat-bubble-mt`）
4. **`.sully-bubble-tail-ai/-user` 守护样式 top 漏了 +mt**（`apps/Chat.tsx:3214-3216, 3217, 3220, 3221, 3222`）—— 都是 `calc(--sully-chat-avatar-size/2)` = 14px，没加 `+ --sully-chat-bubble-mt`，相对气泡顶偏上 8px，恰好落在气泡"中线靠上"
5. **JSX 头像槽 `top-[0.35rem]` = 5.6px**（`MessageItem.tsx:2076, 2140`）与气泡 `margin-top: 8px` 不同源，靠守护样式 `!important` 覆盖为 8px，但源头不一致

### 修复
- `MessageItem.tsx:2012-2032` `renderBubbleTail` 改为两侧统一走 JSX SVG 路径，viewBox 复用 12x12，path 复用，className 切换 `-ai/-user` 由 CSS 控制镜像和宽高
- `MessageItem.tsx:2076, 2140` 头像槽 `top-[0.35rem]` 改为 inline `style={{ top: 'var(--sully-chat-bubble-mt, 0.5rem)' }}`，源头与气泡 margin-top 同步
- `apps/Chat.tsx:3193-3200, 3211-3221` 删除复古微信分支下所有 PNG 引用和伪元素代码（文件不存在，留着也是死代码）
- `apps/Chat.tsx:3195, 3198` 给 AI/user 气泡加 `--sully-bubble-tail-start/end`，让 SVG 渐变与气泡背景同色
- `apps/Chat.tsx:3214-3222` 尾巴 top 全部改为 `calc(--sully-chat-bubble-mt + --sully-chat-avatar-size/2)` = 22px（之前漏了 +mt，差 8px）
- `components/chat/ChromeCssEditor.tsx:317-318, 337-348` 同步删除 PNG 残留；`:319, 322` 同步加 tail 颜色变量

### 项目记忆备注
PROJECT_MEMORY 的 `8月25日-16`（"角色气泡直接使用用户原图"）提到的 `角色气泡单行.png/多行.png` **在仓库里不存在**，是空头支票；现在回退到纯 CSS 渐变 + JSX SVG 尾巴，AI/user 两侧完全对称。
