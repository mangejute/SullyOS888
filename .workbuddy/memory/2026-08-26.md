## 8月26日-8：voice bar 尾巴 SVG 贴齐气泡（去缝）

用户反馈"语音条和气泡尾巴之间有缝，看着有点突兀"。

**根因**：`MessageItem.tsx:3869, 4020` 两处 AI 尾巴 SVG `viewBox="0 0 12 12"`，但 `.sully-bubble-tail-ai` 在 `tailwind.css:111` 设了 `height: 10px`，所以 SVG 容器是 12×10。SVG 默认 `preserveAspectRatio="xMidYMid meet"`——保持比例，垂直缩放 0.833，**水平**也按 0.833 缩（meet 要求全显示），导致 viewBox x=12（底边右端）落在容器 x=10 处 = 父级 -2px。**和气泡框左缘（父级 0）有 2px 缝**。

**修复**：两个 SVG 加 `preserveAspectRatio="none"`，让 viewBox 12×12 强制拉伸到 12×10 容器——viewBox x=12 落到容器 x=12 = 父级 0，**水平贴齐气泡左缘**，无缝。垂直方向拉伸让三角形变扁（10/12=0.833），但高度本来就是期望 10px。

只改 `MessageItem.tsx:3869, 4020` 两个 SVG 的属性（各加一行），不碰 tailwind.css 也不碰 AI 文字气泡（回滚后 AI 文字气泡 `renderBubbleTail` 仍返 null，不渲染 SVG tail，这条修改不会影响它）。

## 8月26日-13：SVG 尾巴改作 voice bar 框的子元素（修复 z-index 失效）

**根因**：8月26日-12 修复 z-index 3 没生效——SVG 尾巴 `<span>` 是 voice bar 框 `<div className="max-w-[260px]">` 的 **sibling**（两者都在 `<div className="relative z-10">` 内）。虽然 SVG 设了 `z-index: 3`，但 voice bar 框（z-index auto + DOM 顺序在 SVG 之后渲染）会**部分覆盖** SVG 的右半部分，尖角"3px 露出 + 9px 被覆盖"视觉上看不到。

**修复**：把 SVG 尾巴 `<span>` 从 voice bar 框外的 sibling 改为 voice bar 框的**子元素**，同时 voice bar 框 `<div className="max-w-[260px] -ml-2">` 加 `relative` className，让它成为 SVG 的定位父级 + 自身的 stacking context。这样 z-index 3 在 voice bar 框的 stacking context 里成立——SVG 尾巴一定在 voice bar 子元素之上。

两条分支（`voiceData?.url` + `hasVoiceTag`）都改。`tailwind.css` 不动，`sully-bubble-tail-ai` 类不动（只是 SVG 在 voice bar 框内）。构建：8月26日-13 成功（Chat-D1jUnrZc.js）。

**服务器**也改了：`local-static-server.cjs` 给 `assets/` 下的 js/css/json 返回 `Cache-Control: no-store, no-cache, must-revalidate` 头。但 SW 缓存先于 server 头——用户**必须** Unregister SW 或**开无痕窗口**。
